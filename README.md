# Prerequisites

CRE TS SDK currently requires [the BunJS runtime.](https://bun.com/).

# How to use - Method 2

In this method you initialise your new CRE project with `cre-init`.

1. run `cre init` and then choose a project name.

2. If there is currently no package.json in your directory tree you will be asked to choose between golang and TypeScript. Choose TypeScript.

3. You can pick the default template. Later on you can copy and paste one of the more advanced examples from `./src/workflows` and paste into your newly created project.

4. the workflow directory is nested under the project you specified when you ran `cre init`. cd into the workflow directory - note there is a `package.json` file there. From inside that directory run `bun install`.

Make sure that you see this in your terminal:

```
$ bunx cre-setup
✅ CRE TS SDK is ready to use.
```

If you do not see that then run `bunx cre-setup` inside that workflow directory. You should expect to see `✅ CRE TS SDK is ready to use.`.

5. In a new terminal window, git clone the CRE CLI into a **different directory** and run the build command specified in the CLI's README so that you have the `cre` executable in that project's root. For me the `cre` cli executable is in `"/Users/zubinpratap/code/cre-cli/`. Test that `cre` tool works by calling `cre version`.

6. Back in your workflow directory, alias `cre` to point to the cre executable that you built previously. For me it looks like
   `alias cre="/Users/zubinpratap/code/cre-cli/cre"`

7. In your workflow directory note that the workflow is specified in the `main.ts` file when it is generated by the `cre init` command. To run the simulator we run `cre workflow simulate --target local-simulation --config config.json main.ts`
